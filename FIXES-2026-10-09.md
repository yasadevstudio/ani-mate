# ANI-MATE — seasons, grouping and hybrid search
*2026-10-09. Five reported problems; six root causes, because one of them had two.*

## 1. Season 3 opened Season 2

`groupByFranchise()` chose the entry the franchise card opens by sorting on
**format rank, then episode count descending**. A season that is still airing has
the FEWEST episodes, so it sorted last and `members[0]` was the previous season.
Apothecary Diaries S3 (1 aired episode) lost to S2 (24) every time. Tokyo
Revengers and Frieren had it too.

Sorting now runs on release date, which was never being requested from AniList at
all. `startDate`/`seasonYear` were added to the query and reduced to one sortable
integer in `dateKey()`.

**Underneath it was a second, worse bug.** `findAniMatch()` pass 2 stripped the
season marker off BOTH sides before comparing, so `Kusuriya no Hitorigoto Season 3`
matched the **Season 1** AniList entry and inherited its date, cover, description
and genres. Every later season of every show was being described as its first.
Passes 2 and 3 now require the season numbers to agree.

## 2. Franchise cards fired twice per tap

`bindCards()` selected `.result-card`, which franchise parents also carry, and
`bindFranchiseToggles()` bound them again. Two handlers, two `loadEpisodes()` calls.
Scoped to `.result-card:not(.franchise-parent)`.

## 3. No way to reach another season from the episode panel

`loadEpisodes()` had been storing `franchiseId` on `state.selectedAnime` and
nothing ever read it. There is now a season strip above the episode grid listing
every entry in the franchise, chronologically, current one highlighted.

Siblings come from whatever list you clicked from. Arriving from favourites or
history means they were never fetched, so `ensureFranchiseSiblings()` does one
lazy search on the season-stripped title and caches the result.

## 4. The same show appeared twice, once orphaned

`Frieren: Beyond Journey's End` and `Sousou no Frieren` are one show and both come
back from AllAnime. The English one never grouped, because **AniList writes
`Journey’s End` with U+2019 and AllAnime writes `Journey's End` with an ASCII
apostrophe**. `normName` stripped the ASCII one and left the curly one, so the two
titles were never equal.

`normName` now folds unicode punctuation to ASCII before stripping — curly quotes,
primes, the full dash family, fullwidth brackets, the katakana middle dot. Patched
in all 9 places it is defined. There is also a last-chance pass that groups any
result still lacking a `franchise_id` whose season-stripped title matches one that
has it.

## 5. Search was neither hybrid nor ranked

Both sources match TITLES only: AllAnime does a substring match, AniList's
`search:` is a fuzzy title match. Neither looks at what a show is about. And the
two were **concatenated, not merged** — AllAnime's order was kept and AniList-only
titles appended, capped at an arbitrary 3. There was no scoring anywhere.

Two separate pieces were needed, because **scoring cannot fix retrieval**. A query
like "giant titans eat humans behind walls" returned zero candidates, so there was
nothing to rank.

**Ranking** (`rankResults`) blends a keyword score over titles/synonyms with BM25
over description, genres and tags. The weighting is **adaptive**: content earns
real weight only when nothing matched a title well. A fixed split ranked
`Cowboy Bebop` below `Cowboy Bebop: Tengoku no Tobira`, because the movie's synopsis
repeats the franchise name while the 26-episode series carries no description at
all. A missing description is also treated as missing DATA — it inherits the set's
median rather than scoring zero.

**Retrieval** (`server/search-index.js`, `mobile/www/js/ani-mate-index.js`) keeps a
local corpus of descriptions, genres and tags and runs BM25 over it when the title
search finds nothing that matches a title. The corpus grows from ordinary use and
seeds itself from AniList's popularity ranking: 600 entries on the server, lazily
on mobile into localStorage.

The secondary-lookup cap went from 3 to 8.

### What this is, precisely

**Lexical** semantic search, not embedding semantic. It finds Apothecary Diaries
for "apothecary in the imperial palace" because the synopsis says exactly that. It
will NOT infer that "medicine girl royal court" means the same thing. That needs a
sentence-embedding model and a vector index — a separate build with a model
dependency. This has neither.

| giant titans eat humans behind walls | Attack on Titan |

| alchemy brothers lose their bodies | Fullmetal Alchemist |
| ninja village hokage | Naruto |

## NOT DONE — deliberately

No version bump, no build, no release. `CLAUDE.md` makes a release one atomic
commit across nine items, and that is a separate instruction.

Two consequences while that is outstanding:
- `dist/` still holds the old packaged build.
- `mobile/android/app/src/main/assets/public/` is what the APK actually ships and
  is build output that nothing copies automatically. These fixes are not in an APK
  until `npx cap sync android` runs.
